# Витрины — умная авто-сортировка файлов/ярлыков в визуальные контейнеры на рабочем столе

Дата: 2026-11-14. Статус: старт разработки (clean room).

## 1. Идея (запрос)
- Визуальные контейнеры на рабочем столе — «стеклянные мини-витрины», в которых лежат программы (ярлыки), файлы и ссылки на обычные папки проводника. Это **не** библиотечные папки Windows.
- Автоматическая компактная сортировка: новый файл/ярлык появляется → «улетает» в подходящую витрину; если подходящей нет — создаётся новая витрина (по правилам/категории).
- Полная настраиваемость: правила, ручной перенос элементов между витринами, исключения, внешний вид.
- Удобный и визуально приятный интерфейс.

## 2. Clean-room исследование (сводка)

Анализ выполнен субагентами по открытым описаниям существующих классов инструментов (визуальные организаторы рабочего стола и rule-based авто-сортировщики). Ниже — только обобщённые механики/паттерны, без копирования кода, ассетов и проприетарных решений.

### 2.1 Механики визуальных контейнеров (что обычно умеют)
- Ограниченные области на рабочем столе (рамки/группы) с свободным размещением, размером, именем; внутри — иконки файлов/ярлыков/приложений.
- Ручная группировка (drag&drop) + опциональная авто-классификация по атрибутам; пресеты «разложить по категориям».
- Режим «портала»: контейнер отражает содержимое произвольной папки (локальной/сетевой), не перенося её физически.
- Переполнение: прокрутка внутри контейнера, компактные/свёрнутые состояния; быстрый показ/скрытие всех контейнеров; снапшоты/профили расположения.
- Визуал: полупрозрачность/«стекло», настраиваемые цвет/прозрачность/шрифты/размер иконок, заголовки/вкладки.

### 2.2 Механики авто-сортировки (что обычно умеют)
- Триггеры: наблюдение за папками (события ФС), ручной запуск/drag-and-drop, расписание.
- Условия: имя/расширение/тип, размер, даты (создан/изменён), иногда содержимое; комбинации условий, приоритет/порядок правил, область действия (какие папки).
- Действия: переместить/скопировать, переименовать (шаблоны), в архив/удалить; динамические подпапки.
- Надёжность: обработка только «завершённых» файлов (не temp/в процессе загрузки), защита от петель, разрешение коллизий имён, журнал действий, предпросмотр/dry-run, отмена.

### 2.3 Недостатки и боли (что обязательно устранить/улучшить)

| Область | Типичные проблемы | Наш ответ в дизайне |
|---|---|---|
| Хрупкая интеграция с рабочим столом/Explorer | Сломанная раскладка после перезапуска оболочки/обновлений, конфликт с нативными иконками | Контейнеры — отдельный слой поверх рабочего стола; состояние/раскладка хранится у нас и восстанавливается; аккуратное обращение с shell-событиями |
| Непрозрачная автоматика | «Файл исчез», непонятно почему и куда; нет отмены | **Журнал + объяснение**: для каждого перемещения — правило/причина; предпросмотр; undo/корзина; индикатор «новое/неразобранное» |
| Ложные срабатывания и сложность правил | Широкие правила, дрейф настроек, трудно отлаживать | Специфичные правила выше общих, явный порядок, dry-run на существующих файлах, пресеты + постепенное усложнение, исключения |
| Незавершённые/временные файлы | Сортировка `.crdownload/.part/tmp`, открытых/залоченных файлов | Детектор стабильности (размер/mtime не меняются N сек, нет блокировки), игнор временных расширений, ретраи с понятной ошибкой |
| Петли и повторная обработка | Правило срабатывает на своём результате | Область действия правил, маркер «обработано», запрет циклов источник→назначение, идемпотентность |
| Конфликты имён и деструктивные действия | Перезапись, случайное удаление | По умолчанию — перемещение с безопасным переименованием при коллизии; удаление/очистка — только явно и обратимо (карантин) |
| Мульти-монитор / DPI / смена разрешения | Контейнеры «уезжают»/теряются | Относительное/привязанное позиционирование, восстановление при смене топологии дисплеев, ограничения в пределах видимой области |
| Производительность | Частые события, большие папки, тяжёлый рендер | Дебаунс/батчинг событий, ограниченный набор наблюдаемых источников, лёгкий рендер (кэш), фоновые операции вне UI-потока |
| Ярлыки/программы vs файлы/папки | Сломанные ярлыки, перенос активных папок | Явные типы сущностей: ярлык/приложение, файл, папка, «портал» на папку; консервативные дефолты для исполняемых и папок, проверка ссылок |
| Портируемость/«залоченность» | Нельзя экспортировать или вернуться к обычному столу | Конфиг/правила/раскладка в открытом формате (JSON), экспорт/импорт, режим «пауза автоматики» и чистый откат |

## 3. Концепция продукта (наша интерпретация)

- **Витрина** — визуальный контейнер на рабочем столе: имя, стиль «стекла», позиция/размер, режим (коллекция элементов / портал на реальную папку), набор элементов.
- **Элемент** — ярлык (.lnk)/приложение, файл или папка. Хранит ссылку на реальный путь + метаданные (тип, откуда пришёл, каким правилом размещён, закреплён ли вручную).
- **Источники наблюдения** — папки, за которыми следим (напр. Рабочий стол, Загрузки, настраиваемые). Новые/изменённые стабильные элементы прогоняются через движок правил.
- **Движок правил** — упорядоченный набор правил: условия → действие (поместить в витрину X / создать витрину категории Y / переместить в папку Z / игнорировать). Поддержка ручного override (закрепить в витрине, никогда не трогать).
- **Реальные папки проводника** — витрина типа «портал» показывает содержимое папки; действие «переместить» реально переносит файл в папку на диске (с журналом и undo), а не только визуально.

## 4. Архитектура (целевой срез)

```
src/
  Vitrines.Core/        # домен и логика без UI
    Models/             # Vitrine, VitrineItem, Rule, RuleCondition, RuleAction, Placement
    Rules/              # IRuleEngine, matcher'ы, приоритизация, объяснение решения
    Sorting/            # классификация, выбор/создание витрины
    Watcher/            # наблюдение ФС, детектор стабильности, очередь событий, анти-петля
    Storage/            # конфиг/раскладка/журнал в JSON, экспорт/импорт
    Actions/            # файловые операции (move/copy) безопасно + undo
  Vitrines.App/         # настольное приложение (Windows)
    DesktopLayer/       # окна-контейнеры поверх рабочего стола
    UI/                 # стеклянные витрины, drag&drop, список/сетка элементов
    Settings/           # редактор правил, источников, внешнего вида
```

- **Стек (предложение):** C# / .NET 8, WPF для настольного слоя (прозрачные окна, эффекты «стекла», интеграция с Windows). Ядро `Vitrines.Core` без зависимости от UI — тестируемо отдельно.
- **Хранение:** `%LOCALAPPDATA%\Vitrines\` — `layout.json` (витрины/элементы/позиции), `rules.json`, `history.jsonl` (журнал). Всё экспортируемо.

## 6. Принципы разработки
- Clean room: реализуем поведение своими словами/архитектурой, опираясь на обобщённые механики; не копируем чужой код/ассеты.
- Автоматика объяснима и обратима по умолчанию.
- Ядро (`Core`) независимо от UI и покрываемо тестами; файловые операции — через абстракции (для тестов и dry-run).
- Язык интерфейса — русский (по контексту пользователя), код/модели — английские имена, комментарии — по делу.
