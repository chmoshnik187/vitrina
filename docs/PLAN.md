# Витрины — умная авто-сортировка файлов/ярлыков в визуальные контейнеры на рабочем столе

Дата: 2026-11-14. Статус: реализован расширенный функционал (правила, «Неразобранное», журнал/фильтры/мульти-откат, кастомизация, экспорт/импорт, dry-run по всем источникам, устойчивость раскладки). Возможна дальнейшая полировка (clean room).

## 1. Идея (запрос)
- Визуальные контейнеры на рабочем столе — «стеклянные мини-витрины», в которых лежат программы (ярлыки), файлы и ссылки на обычные папки проводника. Это **не** библиотечные папки Windows.
- Автоматическая компактная сортировка: новый файл/ярлык появляется → «улетает» в подходящую витрину; если подходящей нет — создаётся новая витрина (по правилам/категории).
- Полная настраиваемость: правила, ручной перенос элементов между витринами, исключения, внешний вид.
- Удобный и визуально приятный интерфейс.

## 2. Clean-room исследование (сводка)

Анализ выполнен по обобщённым механикам/паттернам (визуальные организаторы рабочего стола и rule-based авто-сортировщики), без копирования кода, ассетов и проприетарных решений.

### 2.1 Механики визуальных контейнеров (что обычно умеют)
- Ограниченные области на рабочем столе (рамки/группы) с свободным размещением, размером, именем; внутри — иконки файлов/ярлыков/приложений.
- Ручная группировка (drag&drop) + опциональная авто-классификация по атрибутам; пресеты «разложить по категориям».
- Режим «портала»: контейнер отражает содержимое произвольной папки (локальной/сетевой), не перенося её физически.
- Переполнение: прокрутка внутри контейнера, компактные/свёрнутые состояния; быстрый показ/скрытие всех контейнеров; снапшоты/профили расположения.
- Визуал: полупрозрачность/«стекло», настраиваемые цвет/прозрачность/шрифты/размер иконок, заголовки/вкладки.

### 2.2 Механики авто-сортировки (что обычно умеют)
- Триггеры: наблюдение за папками (события ФС), ручной запуск/drag-and-drop, расписание.
- Условия: имя/расширение/тип, размер, даты (создан/изменён), иногда содержимое; комбинации условий, приоритет/порядок правил, область действия (какие папки).
- Действия: переместить/скопировать, переименовать (шаблоны), в архив/удалить; динамические подпапки.
- Надёжность: обработка только «завершённых» файлов (не temp/в процессе загрузки), защита от петель, разрешение коллизий имён, журнал действий, предпросмотр/dry-run, отмена.

### 2.3 Недостатки и боли — как учтено

| Область | Типичные проблемы | Реализованный ответ |
|---|---|---|
| Хрупкая интеграция с рабочим столом/Explorer | Сломанная раскладка, конфликт с нативными иконками | Отдельный слой окон-витрин, хранение раскладки, попытка привязки к WorkerW, перепривязка при перезапуске оболочки, кламп позиций в видимую область экранов |
| Непрозрачная автоматика | «Файл исчез», непонятно почему и куда; нет отмены | Журнал с причиной/правилом/источником и фильтрами, dry-run (папка/все источники), откат одного и нескольких действий, «Неразобранное» с причинами |
| Ложные срабатывания и сложность правил | Широкие правила, трудно отлаживать | Богатые условия и исключения, приоритет/порядок, правило-исключение, глобальные «не трогать», пресеты, политика для неподошедших |
| Незавершённые/временные файлы | Сортировка `.crdownload/.part/tmp` | Детектор стабильности, игнор временных расширений, анти-петля (`MarkSelfProduced`) |
| Конфликты имён и деструктивные действия | Перезапись, потеря | Move с безопасным переименованием при коллизии, явный журнал, управляемое хранилище, откат |
| Мульти-монитор / DPI / смена разрешения | Контейнеры «уезжают» | Сохранение позиций/размеров, восстановление в пределах виртуального экрана при показе |
| Производительность | Частые события, большие папки | Дебаунс/очередь, ограниченные источники, опциональная рекурсия, фоновые операции вне UI-потока |
| Ярлыки/программы vs файлы/папки | Ошибочная обработка | Типы сущностей, закрепление вручную, условия/исключения по типу, порталы как реальные папки |
| Портируемость | Нельзя экспортировать | Конфиг/раскладка/правила/инбокс/история в JSON, экспорт/импорт снапшота (zip) |

## 3. Концепция продукта (реализовано)

- **Витрина** — визуальный контейнер на рабочем столе: имя, стиль, позиция/размер, режим (коллекция элементов / портал на реальную папку), набор элементов.
- **Элемент** — ярлык/приложение, файл или папка. Хранит путь, метаданные, источник правила, признак закрепления.
- **Источники наблюдения** — настраиваемые папки (по умолчанию Рабочий стол, Загрузки), опционально рекурсивно. Новые стабильные элементы прогоняются через движок правил.
- **Движок правил** — упорядоченный набор правил: условия (расширения, тип, имя/маски/regex, размер, даты, источник) + исключения → действие (поместить/создать витрину, переместить в папку, отправить в «Неразобранное», игнорировать). Поддержка правил-исключений, глобальных «не трогать», политики для неподошедших и ручного override (закрепление).
- **«Неразобранное»** — очередь с причинами для элементов, не подошедших под правила (по политике) или завершившихся ошибкой; быстрые действия.
- **Реальные папки проводника** — портал отражает содержимое папки; перемещения в портал/из портала выполняются как реальные файловые операции.

## 4. Архитектура (текущая)

```
src/
  Vitrines.Core/        # домен и логика без UI
    Models/             # Vitrine, VitrineItem, Rules (conditions/actions), History/Inbox
    Rules/              # IRuleEngine, SimpleRuleEngine, DefaultRules, FileFacts
    Sorting/            # SortingOrchestrator (watch→rules→actions→history/inbox)
    Watcher/            # FileWatcherService (debounce, stability, exclusions, recursive, anti-loop)
    Storage/            # IWorkspaceStore, JsonWorkspaceStore, VitrineStorage
    Actions/            # IFileOperator, FileOperator (safe move/undo)
  Vitrines.App/         # настольное приложение (WPF)
    Desktop/            # VitrineWindow, DesktopVitrineManager, IconHelper (desktop layer)
    MainWindow.*        # панель: сводка, правила, inbox, журнал, dry-run, вид/настройки, экспорт/импорт
```

- **Стек:** C# / .NET 8, WPF. Ядро `Vitrines.Core` без зависимости от UI.
- **Хранение:** `%LOCALAPPDATA%\Vitrines\` — `layout.json`, `rules.json`, `settings.json`, `inbox.json`, `history.jsonl`, `storage\...`. Экспорт/импорт снапшота в zip.

## 6. Что можно развивать дальше (полировка)
1. **Визуал:** Acrylic/Mica, более богатые анимации перемещения/появления, расширенные пресеты тем.
2. **Интеграция:** углублённая и более надёжная привязка к слою рабочего стола на разных сборках Windows, дополнительные сценарии мульти-монитора.
3. **Правила/UX:** drag&drop-переупорядочивание правил, ещё более наглядный конструктор, подсказки на основе содержимого инбокса.
4. **Качество:** автоматические тесты ядра, телеметрия локального аудита (по желанию), дополнительные действия (переименование/шаблоны).

## 7. Принципы разработки
- Clean room: реализуем поведение своей архитектурой, опираясь на обобщённые механики; не копируем чужой код/ассеты.
- Автоматика объяснима и обратима по умолчанию.
- Ядро (`Core`) независимо от UI; файловые операции — через абстракции.
- Язык интерфейса — русский, код/модели — английские имена.
